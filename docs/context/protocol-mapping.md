## Data Quality Classification

Each reading carries a `quality` enum (Ley 21.719 / DAT-06 compliance):

| Quality | Description | When assigned |
|---------|-------------|---------------|
| `measured` | Direct hardware measurement | Normal ingest from meter via any protocol |
| `estimated` | Interpolated or calculated value | Backfill, gap interpolation, or uncertain IoT quality=1 |
| `invalid` | Failed validation or corrupt | Out-of-range, CRC error, or IoT quality≥2 |
| `unknown` | Quality not determined | Legacy data or source without quality metadata |

### IoT Quality → Reading Quality Mapping

Source: `common/constants/reading-quality.ts` → `mapIotQualityToReadingQuality()`

| IoT quality (int) | Meaning | reading_quality |
|------------------:|---------|-----------------|
| 0 | Good / measured | `measured` |
| 1 | Uncertain | `estimated` |
| 2+ | Bad / offline | `invalid` |
| null | Not set | `unknown` |

## Register Mapping Model

Custom mappings per tenant/device are stored in `register_mappings`:

```
register_mappings {
  protocol      — Protocol code (modbus, mqtt, bacnet, snmp, api)
  device_profile — Hardware model (pac1670, siemens-poc3000, custom)
  register_key  — Raw field name from device (e.g., "active_power_w")
  target_field  — Normalized readings column (e.g., "power_kw")
  scale_factor  — Multiplication factor (e.g., 0.001 for W→kW)
  unit          — Output unit label (e.g., "kW")
  tenant_id     — NULL = global template, UUID = tenant-specific override
}
```
