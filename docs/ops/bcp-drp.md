## 3. Disaster Recovery Scenarios

### Database failure (RDS) (Critical)

1. Detect: CloudWatch DatabaseConnections drops to 0 or FreeStorageSpace alarm
2. Assess: Check RDS console for instance status, Multi-AZ failover status
3. Recover: If instance down → restore from latest automated snapshot (PITR)
4. Apply: Run pending migrations via ECS Exec (docs/ops/rds-migrations-via-ecs-exec.md)
5. Verify: Run smoke tests (npm run test:smoke-dashboard)
6. Notify: Inform stakeholders of incident and recovery time

### Backend service crash (ECS) (High)

1. Detect: ECS service events show task stopped, CloudWatch 5xx alarm
2. Assess: Check ECS task logs in CloudWatch for crash reason
3. Recover: ECS auto-restarts tasks (desired count). Manual: force new deployment
4. Verify: curl health endpoint, run smoke tests
5. Escalate: If recurring, check for OOM (increase task memory) or code bug

### Frontend unavailable (S3/CloudFront) (High)

1. Detect: CloudFront 5xx error rate alarm or user reports
2. Assess: Check S3 bucket accessibility, CloudFront distribution status
3. Recover: Redeploy frontend (deploy.sh), invalidate CloudFront cache
4. Verify: Access platform URL in browser

### IoT data pipeline interruption (Medium)

1. Detect: offlineAlerts Lambda detects stale meters (>4h threshold)
2. Assess: Check IoT Core MQTT connectivity, S3 raw data flow, Lambda errors
3. Recover: Restart iot-ingest Lambda, verify MQTT connection from device
4. Backfill: Run backfill job for gap period (automatic via IngestModule)
5. Verify: Check readings/latest for affected meters

### Security breach / data exposure (Critical)

1. Detect: GuardDuty alert, audit log anomaly, or external report
2. Contain: Rotate JWT_SECRET + COOKIE_SECRET, revoke all refresh tokens
3. Assess: Review audit_logs for unauthorized access patterns
4. Notify: PASA within 24h (CYB-16), Ley 21.719 breach notification within 72h
5. Remediate: Patch vulnerability, force password/MFA reset for affected users
6. Post-mortem: Document incident, update security procedures

### Full region outage (us-east-1) (Critical)

1. Detect: AWS Health Dashboard reports regional outage
2. Assess: Determine estimated recovery time from AWS
3. Communicate: Notify PASA and all tenants of outage
4. Wait: Most services auto-recover with AWS region restoration
5. Recover (if extended): Restore RDS from cross-region snapshot (if configured)
6. Verify: Full smoke test suite after restoration
