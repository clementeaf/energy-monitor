## 1. Change Lifecycle

```
Feature Request / Bug Report
  → Branch (feat/*, fix/*, refactor/*)
    → Development (local + tests)
      → Pull Request (code review + CI)
        → Approval (1+ reviewer)
          → Merge to main
            → CI Build + Deploy
              → Post-deploy verification
```

---

## 2. Branch Strategy

| Branch | Purpose | Protection |
|--------|---------|------------|
| `main` | Production-ready code | Requires PR, CI pass, 1+ approval |
| `feat/*` | New features | Developer branch, rebased on main |
| `fix/*` | Bug fixes | Developer branch |
| `refactor/*` | Code improvements | Developer branch |

## 6. Deployment Process

| Step | Action | Responsibility |
|------|--------|----------------|
| 1 | Merge PR to `main` | Developer + Reviewer |
| 2 | CI builds Docker image → ECR | Automated (GitHub Actions) |
| 3 | ECS deploys new task definition | Automated or manual trigger |
| 4 | Frontend builds → S3 + CloudFront invalidation | Automated |
| 5 | Apply DB migrations via ECS Exec | Manual (ops) |
| 6 | Smoke test (`npm run test:smoke-dashboard`) | Manual (ops) |
| 7 | Monitor CloudWatch for 30min post-deploy | Ops |

---

## 7. Rollback Procedure

| Scenario | Action |
|----------|--------|
| Backend regression | Redeploy previous ECR image tag |
| Frontend regression | Redeploy previous S3 build + invalidate CF |
| Database migration issue | Apply rollback SQL (manual, documented per migration) |
| Full rollback | Restore RDS from snapshot + redeploy previous images |

---

## 8. Emergency Changes

For critical security patches or production-down scenarios:

1. Hotfix branch from `main`
2. Minimal fix + targeted tests
3. Expedited review (1 reviewer, can be async)
4. Deploy via `security-patch-v2.yml` or manual ECS update
5. Post-mortem within 48h
