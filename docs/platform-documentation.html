1. Vision General de la Plataforma

Energy Monitor es una plataforma de monitoreo energetico multi-cliente desarrollada para Globe Power. Permite la gestion, visualizacion y analisis del consumo electrico de edificios comerciales e industriales en tiempo real.

Objetivos Principales

Monitoreo en Tiempo Real

  • Lecturas cada 15 minutos
  • 875 medidores activos
  • Status online/offline/alarma
  • Drill-down jerarquico

Gestion Financiera

  • Facturacion automatica
  • Tarifas por bloque horario
  • Dashboard ejecutivo
  • Comparativos entre edificios

Compliance y Seguridad

  • Ley 21.719 (ARCO+)
  • ISO 27001 alineado
  • Anexo 07 PASA (~88%)
  • MFA por rol

Clientes y Temas

Tema Cliente Medidores Edificios Fuente de Datos
PASA Parque Arauco S.A. 875 (PAC1670/PAC1651) 5 malls CSV + billing XLSX
Siemens Siemens (POC3000) IoT (451 variables) Variable MQTT via IoT Core

3. Autenticacion y Control de Acceso

3.1 Flujo de Autenticacion

La plataforma soporta dos proveedores OAuth: Microsoft (MSAL redirect) y Google (credential flow). El flujo completo:

Usuario ingresa a plataforma
↓
Selecciona proveedor OAuth (Microsoft / Google)
↓
Redirect a proveedor → Login → id_token
↓
POST /auth/login { provider, token }
↓
Backend verifica JWT via JWKS (RS256)
↓
Enlaza identidad OAuth con usuario pre-provisionado
↓
MFA requerido? → QR + TOTP validate
↓
Emite cookies httpOnly (access + refresh token)
↓
GET /auth/me → { user, tenant, permissions }
↓
Frontend: Zustand store + enrutamiento por permisos
Importante: Los usuarios no se autocrean al hacer login. Deben ser pre-provisionados desde /admin/users con rol y edificios asignados. El primer login OAuth vincula la identidad con el registro existente.

3.2 Roles y Permisos

Rol Nivel Acceso Descripcion
SUPER_ADMIN Global Todo Administrador de plataforma (Globe Power). Cross-tenant.
CORP_ADMIN Tenant Todos los edificios del tenant Administrador corporativo (ej: PASA)
SITE_ADMIN Edificio Edificios asignados Administrador de sitio (ej: Mall Grande)
OPERATOR Edificio Edificios asignados Operador tecnico (sin billing)
ANALYST Edificio Lectura + export Analista de datos energeticos
TENANT_USER Locatario Sus medidores Usuario locatario (ej: tienda en mall)
AUDITOR Lectura Todo (solo lectura) Auditor de compliance

Modelo de permisos

Cada permiso es una combinacion de modulo + accion:

  • modulo = vista funcional (ej: admin_users, billing, reports)
  • accion = read, create, update, delete, export

Backend: @RequirePermissions('modulo', 'accion') en cada controller. Frontend: usePermissions() + ProtectedRoute.

3.3 MFA y Seguridad de Sesion

MFA (TOTP)

  • Enforcement por rol (require_mfa)
  • QR directo en login si usuario nuevo
  • Recovery codes de respaldo
  • Apps: Google/Microsoft Authenticator

Sesion

  • Access token: cookie httpOnly (24h)
  • Refresh token: rotacion automatica
  • Idle timeout: 15 min (configurable 5-60)
  • Deteccion de robo de refresh token
  • Cookie prefix: __Host- (prod)

  +------------------+     +------------------+     +------------------+
  |  Globe Power     |     |   PASA           |     |   Siemens        |
  |  (super_admin)   |     |   (tenant)       |     |   (tenant)       |
  +--------+---------+     +--------+---------+     +--------+---------+
           |                        |                        |
           |  Cross-tenant          |  Scoped                |  Scoped
           |  (ve todo)             |  a sus edificios       |  a sus edificios
           v                        v                        v
  +--------+------------------------+------------------------+---------+
  |                    BASE DE DATOS (tenant_id en cada fila)          |
  +--------------------------------------------------------------------+

Cada request incluye x-tenant-id como header. El backend scopes automaticamente todas las queries por tenant. super_admin puede operar cross-tenant sin header.
